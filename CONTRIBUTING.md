# Руководство по внесению вклада в проект «МастерВарка»

Мы рады приветствовать вклад сообщества домашних и крафтовых пивоваров, а также разработчиков TypeScript и React!

---

## 🛠️ Структура проекта

- `src/components/` — React-компоненты пользовательского интерфейса (Калькулятор, Склад, Каталог, Лаборатория этикеток).
- `src/data/` — Базы данных: 34 стиля BJCP, линейка Курского солода, мировые хмели, дрожжи Mangrove Jack’s и Fermentis.
- `src/utils/` — Математическое ядро пивоварения (формулы Tinseth, Palmer, de Clerck, Morey, парсеры BeerXML и Бир.РФ).
- `server/` — Модульный серверный слой Express:
  - `server/routes/` — маршруты API (`ai.ts`, `recipes.ts`, `sync.ts`, `community.ts`, `project.ts`).
  - `server/services/` — безопасность (SSRF защита `security.ts`) и ИИ-шаблоны (`prompts.ts`).
  - `server/types/` — строгая типизация запросов и ответов (`api.ts`).
- `tests/` — Набор модульных тестов Vitest для проверки расчетов и безопасности.

---

## 🚀 Как начать разработку локально

1. Склонируйте репозиторий:
   ```bash
   git clone https://github.com/pippopil/-.git
   cd -
   ```

2. Установите зависимости:
   ```bash
   npm install
   ```

3. Запустите сервер разработки:
   ```bash
   npm run dev
   ```

4. Запустите модульные тесты:
   ```bash
   npm test
   ```

5. Проверьте типизацию TypeScript:
   ```bash
   npm run lint
   ```

## 🍺 Добавление новых ингредиентов и стилей BJCP

- Для добавления новых сортов солода, хмеля или штаммов дрожжей редактируйте `src/data/defaultData.ts`.
- Для добавления новых стилей BJCP редактируйте `src/data/bjcpStyles.ts`. Убедитесь, что указаны корректные диапазоны OG, FG, ABV, IBU, EBC и BU:GU.
- Все расчеты должны сопровождаться тестами в `tests/brewingMath.test.ts`.

---

## 🔒 Требования к безопасности

- Любые функции, запрашивающие внешние URL (парсинг рецептов), обязаны проходить валидацию через `validateExternalUrl` в `server/services/security.ts`.
- Запрещены прямые вызовы приватных IP-сетей, loopback (`localhost`, `127.0.0.1`) и облачных метаданных.
- Секретные ключи API (`GEMINI_API_KEY`) не должны попадать в клиентский бандл.

## 📬 Отправка Pull Request

1. Создайте ветку от `main` (`git checkout -b feature/awesome-feature`).
2. Внесите изменения и убедитесь, что тесты проходят: `npm test && npm run lint`.
3. Сделайте коммит с понятным описанием согласно Conventional Commits: `feat(calc): ...` или `fix(ui): ...`.
4. Создайте Pull Request в основной репозиторий.
